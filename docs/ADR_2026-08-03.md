# ADR-016 · Correction Rail as a Universal Pipeline Primitive · **ACCEPT**

**Decision.** Every semantic change to a document is a `CorrectionRecord`. There is
exactly one place corrections enter the pipeline and exactly one hook that produces
them, and neither knows which provider extracted the document.

| | |
|---|---|
| Problem | Corrections entered through seven hand-rolled call sites, three of them behind `if not _mathpix_path:`. A native document and an imported one had different correction semantics for the same asset type. |
| Evidence | Six cross-source verification blocks in `phase1_pipeline.py`, each repeating findings → corrections → apply. Reviewer heading edits mutated the document directly, so undo was impossible. Artifact suppression would have deleted content with no record. |
| Decision | `SemanticVerifier.inspect(document, **context)` is the single producer hook; `engine.run_inspection()` asks every registered verifier; `engine.record_findings()` is the single entry point. Provenance travels on `Document.import_provider`, read by verifiers themselves — never branched on by orchestration. |
| Consequence | Adding an asset type, or a new import provider, requires no edit to the pipeline. A single-source asset type (artifact suppression) registers exactly like a cross-source one. |
| Trade-offs | One broad `except` per verifier in `run_inspection` isolates failures but can hide them — this bit once, silently dropping 34 suppressions. Mitigated: log level raised to ERROR with exception type, plus a contract test that calls every registered verifier with the exact pipeline context. |
| **Risk** | Low — additive; the rail already existed, this removed the branches around it |
| **Rollback** | Re-introduce per-asset call sites; the verifier interface is unchanged |
| **Success** | Zero `if provider` branches in `phase1_pipeline.py`; reject/undo works for every asset type through the same API |

**Known leak (open).** `src/mathpix/ingestor.py::_register_figures` extends
`verification_findings` directly, so import-time figure findings never become
`CorrectionRecord`s. Tracked debt, not a design exception.

# ADR-017 · Detection Produces Evidence, Not Assertions · **ACCEPT**

**Decision.** A detector emits named, weighted signals and a confidence derived from
them. It does not emit a bare classification.

| | |
|---|---|
| Problem | Heading detection was a first-match cascade of tiers. When it was wrong there was no way to ask *why*, and no way for a later stage to disagree on measured grounds. |
| Evidence | Five tiers, each re-deriving "is this a running header" from its own local heuristics. `Heading.confidence` was unset on the native path. |
| Decision | `src/headings/heading_signals.py` owns five named signals in declared precedence; `EvidenceBundle` computes a weighted-mean confidence; `Heading.evidence_items` records which fired. Decisions were proven byte-identical to the tier cascade via a 248-row corpus dump diff before the cascade was removed. |
| Consequence | A signal can be retired on measured grounds. `positional_h1_slot` was: of 87 content headings, exactly 4 rested on it alone and all 4 were wrong — which became `HEADING_VERIFY_006`, a finding, not a silent deletion. |
| Trade-offs | `SemanticObject.confidence` is written by both the detector (detection strength) and the cross-source verifier (match confidence) — one field, two meanings. Documented on the field; read `evidence_items` when detection strength is what you mean. |
| **Risk** | Low — proven decision-identical before the old path was removed |
| **Rollback** | Signals are pure functions; the cascade is recoverable from history |
| **Success** | Every native heading carries the signals that argued for it |

# ADR-018 · `ContentStream` Is a Derived Traversal, Not the Model · **ACCEPT**

**Decision.** Reading order is expressed as a stream that is **computed on demand and
never stored**. The stream is one linearization of the document; it is not the
document.

| | |
|---|---|
| Problem | Both projections reconstructed reading order independently; `docx_generator` re-derived it a second time by parsing Markdown. |
| Evidence | Four edges no stream position can express, all already in production: `Callout.heading_id`; a `Footnote`'s anchor *and* its body (one object, two positions); `Paragraph`'s containment of its lines; `NoteType` FOOTNOTE vs ENDNOTE — the same object placed by policy, i.e. one graph, two linearizations. |
| Decision | Four rules: identity lives on nodes not stream positions; the stream is derived, never stored on `Document`; nodes reference and never copy; it is named as a traversal so a second one is additive. |
| Consequence | A second traversal (column-aware, logical vs print) is additive. A future graph would produce streams rather than replace them: `build_content_stream(document)` becomes `graph.traverse(...)` — one signature, no rewrite. |
| Trade-offs | Recomputed per use. Negligible at document scale, and the alternative — persisting it — creates a second home for reading order, free to drift. That is the exact defect being removed from Markdown, recreated one layer up. |
| **Risk** | Low — additive, no consumer at introduction |
| **Rollback** | Delete two modules; nothing depends on them |
| **Success** | P3 renders from the stream and passes ADR-020's gate |

**Explicitly not decided.** No `DocumentGraph` subsystem. ADR-015's rejection stands.
Relationships are typed, directional and id-based (ADR-019); traversal stays an
implementation concern. If relation traversal ever becomes a consumer requirement,
the edges are already in the vocabulary a graph would need.

# ADR-019 · The Semantic Document Owns Semantics; Projections Consume · **ACCEPT**

**Decision.** Every semantic decision belongs to the model. A projection chooses
syntax and decides nothing else.

| | |
|---|---|
| Problem | The Markdown renderer decided what was prose, how lines grouped into paragraphs, what a note was called, which lines a table owned, and where a heading went. The DOCX projection then recovered those decisions by parsing Markdown — one decision, made inside a format, reconstructed by the next format down. |
| Decision | Paragraph grouping and prose segmentation → `src/structure/paragraph_assembly.py` (pipeline Stage 5c). Note labelling → `Footnote.label`. Table containment → `Table.source_block_ids` via `src/structure/relationships.py`. Heading placement → `Heading.source_block_id` + `continuation_block_ids`. |
| Edge vocabulary | Typed, directional, id-based, added one at a time where needed. `Paragraph.source_orders` (a page-scoped positional key) became `source_block_ids`, removing one of the five different idioms the repository used for the same kind of reference. |
| Rejected | `TextBlock.claimed_by`. The segmentation's own output already records which blocks a paragraph contains, by id; a reverse edge would store the same fact twice and give it a second place to drift. It earns its place when something needs to ask "what claimed this line?" rather than "is this line prose?". |
| Consequence | `_render_page_body_with_paragraphs` fell from 130 to 97 lines and now emits three things instead of deciding six. Absorbed-beats-heading precedence is preserved by splitting `absorbed_block_ids()` from `heading_anchor_block_ids()`. |
| Behaviour | Output changed on 3 of 10 benchmark documents, with the word multiset identical in all three (0 lost, 0 gained). 20 headings appeared, 0 disappeared: the pre-P2 renderer required a heading's text to equal exactly one extracted line, which `feature_007` falsified in June. `heading_f1` 0.5540 → 0.5672. |
| **Risk** | Medium — widest renderer change to date; mitigated by ADR-020's gate |
| **Rollback** | Revert `0419f7f`; the model fields are additive and harmless if unread |
| **Success** | ADR-020 ok=True corpus-wide; no KPI regression |

# ADR-020 · Projection Correctness Supersedes Byte Parity · **ACCEPT**

Full text: **`ADR_PROJECTION_CORRECTNESS_2026-08-03.md`**. Summary:

| | |
|---|---|
| Problem | Byte parity compares output to its own history, so it defends a defect exactly as hard as it defends correct behaviour. It did: the pre-P2 renderer discarded 20 detected headings while byte parity stayed green. |
| Decision | Correctness is a set of invariants between a projection and the Semantic Document that produced it — PI-1 object realization, PI-2 no invention, PI-3 content conservation, PI-4 authorized absence, PI-5 single realization, PI-6 no reconstruction. |
| Consequence | Needs no ground truth, so it applies to every document RAWRS processes. Any new projection inherits it. Verified against the pre-P2 renderer's own output: exactly 20 `lost_object` violations, the precise set the investigation identified. |
| Layering | Violations block (renderer). Findings are graded (detector defects, model debt). Detector P/R/F1 remains a separate, independent metric. |
| **Success** | `python -m src.benchmark --projection samples/benchmark/pdfs` → ok=True |

# ADR-021 · The Workspace Consumes the Stream and Returns Decisions · **ACCEPT**

Full text: **`WORKSPACE_ARCHITECTURE_2026-08-03.md`** (with `INTERACTION_ARCHITECTURE_2026-08-03.md` for the
session state machine). Summary:

| | |
|---|---|
| Decision | The workspace is **not** a Projection and declares no `ProjectionContract`. It renders the `ContentStream` and returns decisions about objects it was handed by identity — never content to be re-read. PI-1/PI-2 are checked **once, on the stream**, so every surface rendering it is realization-complete by construction. |
| Irreducible | Five abstractions, four of which already exist: `Finding`, `CorrectionRecord`, `ContentStream`, `Document.version`, and **`transaction_id`** — the only new field. |
| New rules | **W-1** a finding is derived, a decision is stored · **W-2** history is append-only, undo is a new decision · **W-3** the unit of history is the transaction · **W-4** validation never blocks an edit, it blocks an export. |
| Reduction | A first draft proposed twelve principles; eight were ADR-016/017/018/PI-6 restated and were merged back. Fourteen concepts were deleted outright — see `WORKSPACE_ARCHITECTURE_2026-08-03.md` §7, which archives them. A workspace needing twelve new principles is forking the Freeze, not inheriting it. |
| Amends | `RAWRS_PROJECTION_ARCHITECTURE.md` §4 — projection `anchors` demoted from *"the whole editing story"* to optional: editing happens on the semantic surface, whose nodes already carry `object_id`. |
| API | Three shapes — `GET /stream`, `GET /findings`, `POST /decisions` — replacing eleven per-object-type mutation endpoints that constitute a second write path (ADR-016 violated one layer above the pipeline). |
| **Risk** | Low — additive; the rail, the stream and the evidence model all pre-date it |
| **Success** | One judgement is one undo; no mutation path exists outside the rail |
