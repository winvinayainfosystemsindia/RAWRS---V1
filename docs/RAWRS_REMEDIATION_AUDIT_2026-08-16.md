## 4. The finding that reorders the ranking

Bruner, measured line by line in its MMD:

```
33 inline markers, all of the form  ${ }^{N}$      e.g. "...as Kruger and Tomasello insist, ${ }^{1}$ there i..."
51 numbered lines, number sequence: 1,2,3,4, 1,2,3,...,47
                                    └ 4 ┘  └────── 47 ──────┘
                                      │              │
                        the genuine conceptual list  the NOTES apparatus
                        (human target: 4 list para)  (human target: 36 note refs)
markers whose number has a matching numbered line: 33 / 33
```

RAWRS today renders **all 51 as a Word numbered list** and **0 as notes**. The human target has **4 list paragraphs and 36 note references**. So one capability fixes three ranked candidates at once:

* candidate 4 (missed notes) — 0 → ~40 paired references corpus-wide;
* candidate 8 (reference-list misclassification) — Bruner's 47 false list items disappear;
* candidate 2's residue — Bruner's list count 51 → 4, matching the target exactly.

**And it is discriminated structurally, not heuristically:** a numbered run is the note apparatus when its numbers are *named by inline superscript markers*; a numbered run nothing references is a list. That is why the false-remediation risk is low — the rule fails closed, leaving a list as a list when no marker points at it.

Every downstream part already exists: `Footnote` with `footnote_id` identity, `NOTE_DEFINITION` stream nodes, the P4c-2 DOCX projection into `word/endnotes.xml`, `FootnoteVerifier` + `PATCH /footnotes/{id}`, and `NOTE_001/002`. **Nothing architectural is missing — only the parse.**

## 6. Answers

**1. Is RAWRS capable of mid-tier remediation today?** **No — but the shortfall is now narrow and named.** Of the 40 Both rows, RAWRS materially satisfies roughly 27, exceeds the human target on 1 (`tblHeader`), is blocked by input on 1 (scanned tables), and fails 9–11 outright — of which the checklist's entire **Footnotes & Endnotes** section (3 rows) is failed on the path scanned documents actually use.

**2. What exactly prevents it?** One class of object the reviewer must rebuild entirely by hand: **notes**. 54 references in the target, 7 produced natively, **0 on Mathpix**, while the Mathpix source carries 61 explicit markers. Everything else is either satisfied, reviewer-correctable, cosmetic, or absent from the input.

**3. Smallest vertical slice that changes the answer:** parse the Mathpix note apparatus into the `Footnote` objects the rest of the system already handles end to end.

**4. Milestone name:** **N-1 — "a superscript that names a body is a note".**

**5. What must NOT be built yet:** the native span-level model (bug_005); heading over-production rules; cross-page stitching; table detection on scanned pages; hyperlinks, TOC, bookmarks, PDF export; list correction routes; `ListItem` identity; any ContentStream change; note *renumbering* or placement policy.

**6. Acceptance gate that proves remediation improved rather than objects moving:** stated against the **human target**, not against RAWRS's own model — see below.

**B+ — deterministic foundation with real reviewer-assisted remediation for six object classes** (headings, tables, images, metadata, reading order, lists-as-rendered), **and one object class missing entirely on the primary path**. ## #1 NEXT MILESTONE

**N-1 — "a superscript that names a body is a note"**: recognise `${ }^{N}$` / `^{N}` / `\textsuperscript{N}` markers in the Mathpix parser as note references, and the numbered run whose numbers those markers name as note bodies.

## WHY IT BEATS THE OTHER CANDIDATES

* It is the **only remaining object class that is entirely absent** on the primary path (0 of 54), and the checklist gives notes three unconditional Both rows.
* The **evidence is in the input** — 61 markers across 4 documents, 33/33 pairing on Bruner — unlike tables, whose 20 missing instances are simply not in the package.
* It **removes a wrong output as well as adding a missing one**: Bruner's 47 falsely-numbered list items disappear, taking candidate 8 with them.
* **Zero new architecture**: `Footnote`, `footnote_id`, `NOTE_DEFINITION`, the P4c-2 projection, `FootnoteVerifier`, the PATCH route and `NOTE_001/002` all exist and are exercised.
* **Low false-remediation risk** by construction: no marker, no note — a numbered run nothing references stays a list.
* The alternatives each fail one of those tests: heading over-production needs a judgement rule (high wrong-answer risk), stitching is editorial, tables are input-limited, and language/TOC/hyperlinks are cheap but cosmetic by comparison.

## EXACT FIRST COMMIT

`src/mathpix/mmd_parser.py` only: recognise the three superscript marker forms and emit them as note references carrying their number and source line, leaving block classification untouched. No ingestion change, no model change, no projection change — provable by parser tests plus a corpus count of markers found (61) versus markers rendered (still 0, because nothing consumes them yet), exactly the shape Commit 1 of P4c-4′ used.
